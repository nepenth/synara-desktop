# Synara 2.1.25

Synara 2.1.25 completes a broad shared-Rust ownership follow-on across timeline
actions, message presentation, notifications, verification eligibility, and
bounded media handling. Desktop and iOS now make the same core decisions while
retaining native presentation and operating-system integration.

## Timeline Actions And Readback

- Reactions, poll votes and clears, reports, encrypted-room forwarding, and
  call declines use shared Rust-owned Matrix operations with typed readback.
- A successful reaction write no longer appears to fail merely because the
  timeline aggregation has not caught up. The interface remains locked until
  authoritative projection confirms the final state.
- Edit, poll, and decline acknowledgements are pinned to the exact target event
  so a same-room response cannot be attributed to the wrong message.
- iOS preserves distinct encryption-unavailable and downgrade-confirmation
  outcomes and presents recovery inside the active forwarding sheet.

## Faithful, Safe Message Presentation

- A shared adversarial corpus now covers Matrix and Hermes paragraphs, replies,
  inline code, code blocks, tables, spoilers, and formatted relationships.
- Desktop and iOS sanitizers preserve useful semantic text while preventing
  resource-bearing image, source, and `mxc://` output from escaping the
  presentation boundary.
- Redaction and late-decryption sequencing are exercised through the production
  projection paths rather than an identity-only test substitute.

## Notifications And Logout

- HTTP-pusher cleanup is scoped to Synara's app identifier and exact device
  identity or last-known key, ignores unrelated non-HTTP pushers, and attempts
  every matching deletion before reporting a failure.
- Logout makes one bounded owner rebind when needed and remains fail-closed if
  homeserver cleanup cannot be completed.
- The notification service distinguishes an unavailable App Group from a user
  who disabled previews and records only fixed, privacy-safe diagnostic stages.
- Desktop Inbox parsing surfaces homeserver error envelopes and accepts an
  explicit `notifications: null` as a valid empty result instead of crashing.

## Verification And Media Boundaries

- Device-verification eligibility prefers the Matrix SDK authority query and
  can project the same predicate over a successfully loaded local device set.
  A failed local fetch stays unknown so the interface continues to offer Retry
  rather than falsely claiming that no eligible session exists.
- Matrix media responses are status-checked, size-bounded, and authenticated
  before presentation. Encrypted media keeps separate bounded ciphertext and
  plaintext allocations, with tests covering both accepted and rejected caps.
- Media cache ownership remains unchanged; this release does not introduce an
  unreviewed cache or expose media bytes through generic command transport.

## Interface And Validation

- Desktop formatting controls use the same quiet interactive depth as adjacent
  composer actions, and the iOS formatting row retains 44-point hit targets
  while fitting compact devices more naturally.
- iOS room-list header spacing is tightened without changing navigation or
  Dynamic Type behavior.
- CI now separates iOS unit and UI lanes on a named arm64 simulator. Main,
  release, nightly, and explicitly opted-in PR runs retain the full UI proof.
- The accepted PR head passed 929 desktop modernization tests, the Rust and
  repository policy suites, all native Matrix interoperability jobs, iOS unit
  tests, 59 iOS UI tests with 14 intentional skips, and macOS, Debian, and Arch
  package smoke.

## What To Test

- React repeatedly to a message while new room events arrive and confirm the
  action never flashes as failed or reverses because of an immediate retry.
- Vote, clear a vote, report, forward between encrypted and unencrypted rooms,
  and decline a call from both desktop and iOS.
- Compare complex Matrix and Hermes messages across dark and light appearances,
  especially spoilers, tables, inline code, replies, and formatted copy.
- Enable notification previews and time-sensitive approvals, then verify push
  delivery, quick actions, and logout cleanup on a physical iOS device.

Physical APNs/NSE delivery, live homeserver pusher-field readback, full
two-client action interoperability, and real-device media memory/cancellation
measurements remain explicit release-validation items rather than simulated
claims.
