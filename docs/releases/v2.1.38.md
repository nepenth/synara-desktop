# Synara 2.1.38

Synara 2.1.38 adopts matrix-rust-sdk 0.19 and lands the approved 0.19 slices:
room history date rail and attachment preview, messaging core, threads, room
surfaces, calls, dehydrated devices, QR verification, default-off widgets,
local search, encrypted state, X.509, and key forwarding.

## Matrix SDK 0.19

- Desktop and shared Core use matrix-sdk 0.19.0, Ruma 0.17, and Rust 1.96
  with `rustls-aws-lc-rs`. Room-list subscriptions and presence writes follow
  the 0.19 APIs.
- QR login / MSC4388 is not in this release.

## Room history and attachments

- The native date rail jumps across the whole room with `timestamp_to_event`.
  The center date chip is hidden while the rail is shown.
- Generic files download through Core. Markdown attachments open a rendered
  preview; Download remains in the header.

## Messaging, threads, rooms, and calls

- Reaction ids are recovered for the native viewer. Composer sends use
  RoomSendQueue and re-enable after a recoverable failure. Pins, last-message
  pagination, and the event cache subscribe at session start.
- Native thread timelines, a Threads panel, hide-threaded live timelines, and
  thread receipts/unreads.
- DM avatars, own-profile updates, MSC1763 retention copy, and link unfurls
  that never preview encrypted or unknown rooms.
- MatrixRTC discovery and MSC4426 in-call/status chrome. No Join/Leave.

## Crypto and experimental

- MSC3814 dehydrated devices as a backup Olm catcher.
- Show-QR device verification with SAS fallback on desktop; iOS stays
  SAS-only.
- Experimental widgets compile in and host in an isolated webview, default
  off.
- Desktop local EncryptedDirectory search. NSE/iOS do not pull Tantivy.
- Experimental MSC4362 encrypted state (opt-in; call rooms never).
- Experimental X.509 identity beside SAS, default off.
- Automatic room-key forwarding on desktop and iOS full-app, not NSE.
