# Synara 2.1.15

Synara 2.1.15 closes the remaining cold-launch lifecycle race behind recent
iOS suspension crashes and makes the macOS composer honor message-text tone.

## iOS Lifecycle Ownership

- The additional TestFlight reports were both `RUNNINGBOARD 0xdead10cc`
  terminations. One process was checkpointing a Matrix SQLite WAL during store
  close; the other was reading SQLite after a notification-time launch while
  iOS suspended the process.
- SwiftUI scene activity and UIKit process activity are now combined into one
  explicit foreground authority. The active app shell is not constructed, and
  Matrix stores cannot open, until both signals say the process is usable.
- Native Matrix startup fails closed before foreground activation. Start,
  pause, resume, and close remain serialized through the shared lifecycle
  owner, while duplicate background callbacks safely coalesce.
- A cold background launch with no active Matrix owner is treated as already
  quiesced. Session replacement preserves foreground authority, preventing a
  relogin from leaving the new session permanently paused.
- Notification Approve and Deny actions now bring Synara to the foreground.
  Their pending response is held until the app is active and Matrix has resumed
  before the shared approval policy sends a reaction.

## Diagnostics and Regression Coverage

- Added a reusable authenticated TestFlight crash-fetch script so future crash
  signatures can be compared without manual App Store Connect copying.
- Added lifecycle tests for cold-background startup, cold pause without an
  owner, duplicate quiescence, foreground gating, deferred notification
  actions, and relogin through the shared core.
- On an iPhone 17 Pro simulator, a disposable live Matrix account completed
  repeated foreground/background transitions. The final store close completed
  in 31 ms, no Matrix SQLite descriptors remained while suspended, and a silent
  push did not reopen them.

## Desktop Appearance

- The macOS message composer now consumes the same semantic message foreground
  variable as rendered messages, so Soft, Balanced, and Bright apply
  consistently while typing and reading.

## Validation

- All focused iOS lifecycle, push, and shared-core tests passed.
- The iOS simulator build completed successfully.
- All 827 desktop modernization tests and the production runtime build passed.
- Runtime asset consistency checks passed.

## What to Test

- Background Synara from a busy encrypted room, leave it suspended, then return
  and confirm the room resumes without a crash or stale session.
- Open an approval notification action from a cold or backgrounded app and
  confirm the reaction is sent only after the session becomes ready.
- On macOS, switch Appearance > Message text among Soft, Balanced, and Bright;
  confirm both existing messages and text in the composer change together.
