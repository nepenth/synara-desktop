# Synara 2.1.8

Synara 2.1.8 completes the Matrix device-verification repair and corrects the
light-mode surfaces on iOS Rooms and Settings.

## Device Verification

- Account sessions can be refreshed before selecting a newly signed-in device,
  preventing the verification flow from targeting a stale historical session.
- The paired iOS diagnostic coordinates by the two exact Matrix device IDs. It
  rejects empty, identical, or fallback targets instead of allowing a
  false-positive path.
- Completed SAS verification uses the Matrix SDK's full device trust result.
  This includes trust established directly by SAS, not only trust inherited
  through cross-signing.
- Both clients must present the same emoji comparison, confirm it, terminate,
  relaunch, refresh Account, and read the exact peer back as **Verified**.

## iOS Surface Continuity

- Rooms and Settings now use quiet, opaque near-white surfaces in Light Mode
  instead of blending in the dark graphite base and producing a gray veil.
- Their content planes extend through the top and bottom safe areas, removing
  the mismatched color bands shown around those two screens.
- Settings keeps its lower-content clearance inside the same background, so the
  floating tab bar does not obscure the final rows.
- Semantic surface and text colors preserve the existing Dark Mode hierarchy
  and adapt to accessibility contrast settings.

## Validation

- Two live iOS simulators completed request, acceptance, key exchange, identical
  SAS emoji comparison, confirmation on both sides, and durable Verified
  readback after both apps relaunched.
- A live two-device Rust proof also required the authoritative product device
  snapshot to report the peer as Verified.
- The full shared Rust workspace, iOS simulator suite, Matrix architecture
  guardrails, release contracts, and light/dark theme contrast tests passed.
- Verification diagnostics contain no passwords, access tokens, device IDs, or
  SAS values in source control or release notes.

## Upgrade Notes

- Existing sessions and crypto stores should restore normally.
- If a newly signed-in session is not immediately visible, pull to refresh on
  Account before opening it.
- Never approve verification when the comparison differs between devices.
