# Synara 2.1.27

Synara 2.1.27 repairs iOS timeline stability and sign-out, and desktop automatic
read acknowledgement.

## Timeline and read state

- Desktop accepts a Core-verified move from unread placement to live even when
  no message row changed. It also detects a fully visible room without requiring
  a scroll event, so short unread rooms can be acknowledged automatically.
- iOS leaves unchanged timeline rows in place and preserves visible anchors
  without first scrolling them to another position.
- iOS coalesces live invalidations by room. Temporary read-marker streams can
  no longer replace an update that the timeline then discards as another stream.

## Sign-out

- Remote push cleanup failure no longer traps the iOS app in a signed-in state.
- iOS attempts an actual, bounded homeserver logout on the current device.
  It then stops local owners and removes persisted authentication, including
  when the SDK session could not restore. Encrypted history and its storage key
  remain available for a later password login.
- Remote cleanup is best effort when the homeserver is unreachable. Local
  deletion failures remain visible and do not report successful sign-out.

## Validation scope

Regression coverage exercises UIKit scroll mutations, browser geometry,
room invalidation delivery, and the Core logout route with a mock homeserver
and credential-vault readback. These checks do not replace a physical-device
verification of the original reported symptoms.

After updating, open an unread room on macOS and check automatic read state.
On iOS, check stationary timeline rows, incoming messages, and sign-out followed
by relaunch. Explicit historical event views retain Jump to latest and cannot
acknowledge unseen messages merely by reaching the bottom of their context.
