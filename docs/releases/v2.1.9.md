# Synara 2.1.9

Synara 2.1.9 adds synced room notes and opt-in encrypted notification previews
to iOS, while strengthening device-verification restore and release safeguards.

## iOS Room Notes

- Room timelines now expose Notes on iOS, matching the account-synced notes
  available on the desktop clients.
- Notes use shared Matrix account data rather than a device-local copy, so
  edits follow the signed-in account across supported clients.
- Loading, editing, conflict handling, and timeline presentation are covered by
  the iOS service and UI test suites.

## Notification Content

- When notification previews are enabled, the iOS notification service can
  resolve encrypted Matrix events and include message content in the alert.
- Preview delivery is exactly-once and cancellation-safe, including concurrent
  resolution, timeout, and extension-expiry paths.
- If the event cannot be resolved within the extension budget, Synara keeps a
  safe generic notification instead of exposing partial or untrusted content.
- The extension uses a purpose-built native core and does not link the full
  application Core. CI verifies the embedded arm64 executable, forbidden
  linkage/exports, and an explicit disk-size regression budget.

## Verification and Settings

- Session restoration resets the verification runtime cleanly without losing
  the durable SDK trust state established by a completed SAS comparison.
- The two-client verification proof completes request, matching emoji or
  decimal comparison, confirmation, relaunch, and Verified readback.
- Lower Settings content remains clear of the floating iOS tab bar.

## Validation

- The focused iOS notification suite passed 138 tests with one live-environment
  skip, including concurrent resolve/cancel coverage.
- Rust notification/core tests, Swift generated-binding tests, and Core
  isolation checks passed.
- The generic-device Release build embedded a 19,928,872-byte arm64 extension
  with no full SynaraCore linkage or UniFFI exports.
- The complete pull-request Quality gate passed, including iOS simulator and
  Release validation, Rust and Node gates, six disposable-Synapse proofs, and
  macOS, Debian, and Arch package smokes.

## What to Test

- Open Notes from an iOS room, edit a note, and confirm it appears on another
  signed-in client for the same account.
- In iOS notification settings, compare message-content previews enabled and
  disabled for clear and encrypted rooms.
- Confirm an encrypted notification falls back safely when the event cannot be
  decrypted before the notification-service deadline.
- Complete device verification on two devices, relaunch both apps, and confirm
  each exact peer session still reads Verified.

Physical APNs delivery and notification-extension memory footprint remain the
post-TestFlight device checks for this release.
