# Synara 3.5.2

Synara 3.5.2 fixes a link preview that appeared under a message that mentions someone, on desktop and iOS.

## Mentions and link previews (desktop and iOS)

- A message that mentions someone could show a link preview card for that person's homeserver, for example a card titled "Synapse is running".
- The cause: a mention has two texts. The formatted one holds the mention itself, a `matrix.to` link that Synara opens and never previews. The plain one spells the user ID out, `@puck:example.org`. When the formatted text had no link to preview, Synara looked in the plain text, and link detection took the server name out of the user ID as a web address.
- Link detection now skips a server name that directly follows the first part of a Matrix ID: `@name:`, `#room:`, `!id:`, `$event:` or `+group:`. This also means the server name of an ID typed into a plain message is no longer a link.
- A real link in the same message still links and still gets its preview.

## Known limits

- The desktop change was checked with unit tests. The iOS rule was checked in a standalone script with the same system link detector, and its unit tests run in CI. Neither was looked at in a running app before the release.
- A colon that is not part of a Matrix ID still allows a link after it, so `note:example.org` links `example.org`.
- The iOS app is still built with the iOS 26 SDK.

## Distribution

The coordinated tag workflow validates the release and publishes signed and notarized macOS downloads and updater metadata, Linux APT and pacman packages, Windows installers, and the internal iOS TestFlight build.
