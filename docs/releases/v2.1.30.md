# Synara 2.1.30

Desktop notifications now follow the account's Matrix push rules through Core's live event stream.

- Room modes, mentions, keywords, edits, and rule ordering are evaluated by the Matrix SDK. Plain group messages use its silent default; one-to-one messages and mentions retain their configured sounds.
- Desktop delivery reports an OS receipt. Bundled macOS apps use one UserNotifications client for authorization, submission receipts, presentation, and actions; refused delivery is counted once without retrying.
- Approval prompts retain their native action buttons, participate in Core dedup and receipt accounting, and no longer play duplicate native and renderer sounds.
- Packaged desktop apps check both IPv4 and IPv6 port ownership before serving their frontend, avoiding collisions with another running version.
- Late notification decisions and acknowledgements cannot cross into a new login session.
- CI now compiles iOS targets when iOS-sensitive feature changes skip the full simulator test lane. Release candidates continue to run both simulator suites.

The observation window remains five minutes and dedup is session-local. A fresh login can surface recent messages again.

Local checks passed 958 renderer tests, 57 notification-related Core tests,
six SDK push-rule integration tests, and the final 11 native notification
tests with all-target Clippy. Updated-head CI runs full Rust/runtime checks,
platform packaging, and both iOS simulator suites before merge.

Signed local macOS smoke verified allowed, denied, re-enabled, and approval
delivery receipts through the real Core stream. Denied delivery did not retry.
This was a signed feature-source smoke, not the final notarized artifact.
All notification settings were restored. iOS validation uses simulators at
the user's request. Final candidate installs, Linux GUI delivery, live action
clicks, audible sound, and a three-member live group remain unverified.
