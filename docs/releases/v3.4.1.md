# Synara 3.4.1

Synara 3.4.1 fixes a room list that showed an old last message for an active room, fixes macOS text replacement in the desktop message box, and makes the iOS app check for a synced draft in more situations.

## Room list (iOS and desktop)

- A room could keep an old last message, time and place in the list while it was active, and show the right one only after you opened it. This was most visible on iPhone after the app had been in the background.
- The cause: after a catch-up the app holds only the newest few events of each room (five for a room that is not among the 20 most recent). When all of them are edits, reactions or deletions, none can be shown as a preview. An agent that streams its reply by editing one message produces exactly this.
- The Matrix SDK handles this case by loading older events in the background until it finds one to show. That option had been off since 2.3.0, because at sign-in it sent about one history request per room. It is on again.
- The same option corrects two other things: a room that showed no last message at all, and unread counts made on the device (used for encrypted rooms), which could not exceed the events held for the room.

### What it costs

Measured against a test server with 30 rooms, with the SDK loading three rooms at a time:

| Situation                                | History requests              |
| ---------------------------------------- | ----------------------------- |
| Sign-in, everything read                 | 1 per room                    |
| Sign-in, read position 100 messages back | 4 per room                    |
| Sign-in, no read position for the room   | 21 per room (the SDK's limit) |
| Later catch-up with new messages         | none                          |
| Pending invite                           | 1, refused by the server      |

The room list shows before this loading finishes.

## Message box on macOS (desktop)

- With "Use smart quotes and dashes" on in macOS, typing two hyphens and then a letter or a space left the hyphens in place with an extra dash after them ("--—"), and typing stopped until you clicked in the message box. The dash now replaces the hyphens and you can keep typing.
- The same fix covers smart quotes, macOS text replacements, autocorrect and a spelling suggestion picked from the menu, in the message box, the thread pane and when editing a message in place.
- The cause: WebKit applies these replacements while it inserts the next typed character, when the page was one character ahead of the editor's own text. The editor took the caret position from the page and inserted the replacement there instead of over the replaced text.

## Synced drafts (iOS)

- A draft written on another device could stay hidden until you left the room and opened it again. The room now also checks for a newer draft when you return to a room that was kept open, when the app comes back to the foreground, and when you finish editing a message.
- A synced draft that could not be shown because you were typing at that moment is offered again; before, it was counted as taken.

## Known limits

- The room list fix was checked with tests that replay a catch-up made only of edits, and the request counts above come from a test server, not a real homeserver. The events of the room in the original report were not inspected, so another cause for the same symptom is possible.
- The message box fix was reproduced and checked in a WebKit view on macOS with the composer test page, not in the packaged app.
- The iOS draft changes were checked by unit tests only. Draft sync has still not been tested between two real devices by this release's checks, and these changes may not be the only reason a draft does not reach a phone: every device needs 3.4.0 or later and must be verified.
- The iOS app is still built with the iOS 26 SDK.
