# Synara 2.1.11

Synara 2.1.11 completes a first-principles pass over Matrix message rendering,
device verification, Hermes agent approvals, and notification delivery while
adding the signed Debian-family package repository.

## Exact Matrix and Hermes Rendering

- iOS formatted messages now render from a typed semantic tree rather than
  sanitizing with regular expressions or reparsing HTML as Markdown.
- The renderer follows Matrix's supported rich-text contract for headings,
  quotes, exact preformatted code, nested lists, ordered-list starts, tables,
  details, spoilers, superscript/subscript, colors, safe links, and Matrix media
  fallbacks.
- Reply fallbacks are removed structurally, unsafe tags, attributes, and URL
  schemes are rejected, input and nesting are bounded, and malformed tables or
  details retain readable descendant text.
- Hidden spoilers stay out of the accessibility tree until revealed, and stable
  content identities prevent unrelated disclosure state from leaking between
  messages.
- Desktop rich-message handling shares the same Matrix/Hermes interpretation for
  code language metadata, links, reactions, and readable fallbacks.

## Device Verification

- Verification diagnostics now record the exact SAS lifecycle and durable trust
  readback without exposing credentials or cryptographic material.
- A paired, signed simulator run proves both roles cross `KeysExchanged`, become
  presentable, display identical emoji/decimal values, confirm, complete, and
  read the peer device back as Verified after both apps are killed and relaunched.
- Cold-launch session readiness retains pending verification and notification
  work until the signed-in services are bound instead of dropping it during app
  startup.

## Hermes Agent Approvals

- Approval-prompt classification and decision policy live in the shared Rust
  core so iOS, macOS, and Linux use the same prompt identity, expiry, choice,
  reaction, and already-decided semantics.
- iOS can present fresh prompts as Time Sensitive notifications with Review,
  authenticated Approve once, and authenticated destructive Deny actions.
- Notification actions are retained across cold launch and fail closed for
  stale, malformed, unresolved, or already-decided prompts. Approve-always
  remains an in-app decision because it has broader scope.
- Desktop notifications distinguish actionable approval prompts and route quick
  decisions through the same native Matrix reaction owner.

## Notification Previews

- The notification extension and app coordinator preserve opt-in decrypted
  message previews when local resolution succeeds and use privacy-safe fallback
  text when it does not.
- Proxy-provided category metadata cannot grant approval controls; only a fresh
  local shared-core classification can attach actionable categories.
- Production APNs and TestFlight preview/action behavior remains the external
  validation target for this release because it requires the deployed proxy,
  production credentials, and a physical device.

## Linux APT Repository

- Tagged releases now publish the Debian package and signed flat APT metadata to
  the fixed `apt-repo` GitHub Release alongside the existing pacman repository.
- Repository generation, signing, signature verification, key publication, and
  version consistency are exercised by focused scripts and CI tests.

## Validation

- PR #1051 passed the aggregate Quality gate, the complete iOS simulator and
  clean device-Release build, shared Rust and desktop Rust suites, Node desktop
  validation, disposable-Synapse native reaction proof, and macOS, Debian, and
  Arch package builds.
- Local focused coverage passed 101 rich-message renderer tests, 130 combined
  renderer/push/approval tests, seven session-coordinator tests, 788 shared Rust
  tests with two ignored, and 825 desktop modernization tests.
- The paired signed verification proof reproduced three clean times and compared
  the exact SAS sequence byte-for-byte between both clients.
- Grok 4.6 High reviewed the implementation; accepted concrete findings were
  incorporated before the final green commit.
