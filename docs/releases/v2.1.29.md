# Synara 2.1.29

Synara 2.1.29 combines the 2026-09-06 client reliability work: last-read
navigation, automatic visible-tail read acknowledgement, quieter chrome, and
honest notification / NSE diagnostics.

## Reading And Navigation

- Room entry restores the last-read event when Core can resolve a visible
  predecessor. If the marker is missing, the current viewport stays put and
  Jump to Last Read remains available. Later background pages must not move
  the viewport on their own.
- A focused room at the newest bottom follows new messages. Jump to Latest
  appears only away from that bottom. A successful new send returns to latest;
  edits do not.
- Automatic unread clearing requires an active focused room whose painted
  remote tail matches Core's visible/receipt pair. Hidden edits and reactions
  do not invent a newer message as the read target.

## Notifications And Verification

- Account push policy suppresses replacement-edit alerts before the pusher is
  registered. New messages still notify.
- Notification taps keep the room id and event id and open surrounding
  history. Encrypted preview, timeline load, and verification eligibility
  failures stay separately coded.
- Settings verification status refreshes from device-authority updates instead
  of a one-shot snapshot.

## Window Chrome And Depth

- macOS keeps the OS titlebar. Linux uses an in-app titlebar whose maximize
  label follows native window state.
- iOS joined room rows use quieter collection depth. Desktop Settings cards
  use the shared fold and contrast tokens.

## Validation Scope

Independent workstream reviews and a combined Grok 4.6 High source review of
PR #1104 accepted this tree with no P1 findings. Combined GitHub CI, including
iOS simulator unit and UI lanes, is the release-branch gate. Physical APNs,
device titlebar drag, and two-client live receipt proofs remain operator
checks; this note does not claim those as confirmed.
