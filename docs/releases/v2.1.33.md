# Synara 2.1.33

Synara 2.1.33 fixes device verification after signing out and back in with a retained encryption store.

## Device verification

- Restore the device's original signed public keys on the homeserver before starting verification. Element can now recognize the requesting Synara device and complete emoji verification.
- Refresh the account identity through the Matrix SDK before selecting another verified session.
- Stop before sending verification if public-key publication cannot be confirmed or the server reports conflicting keys.
- Update device trust, recovery, and backup indicators when SDK secret sharing finishes, without needing to reopen Settings or restart the desktop app.

The native verification repair is shared by desktop and iOS.

## Validation

The existing macOS Synara session completed verification with Element on the first repaired attempt. After restart, the same session showed Verified, Recovery Ready, and Backup Connected; Element independently listed that device as verified.

Local validation passed 896 shared-core library tests, 3 verification integration tests, 966 frontend tests, full TypeScript checking, and live retained-store and durable own-device verification proofs. The live proof no longer pre-queries the initiating device from the responder or forces identity refreshes after confirmation. The release PR additionally runs the required Quality gate, iOS simulator suites, and desktop package builds.

Linux and iOS UI verification were not exercised in the local live proof. Detailed evidence is in [the investigation report](../reviews/2026-09-10-device-verification.md).
