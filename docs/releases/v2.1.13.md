# Synara 2.1.13

Synara 2.1.13 fixes a foreground iOS room crash reported through TestFlight
and reduces message-composer latency while busy rooms are receiving updates.

## Live Timeline Stability

- Timeline diffable-data-source updates are now serialized and coalesced, so a
  nested main-run-loop callback cannot re-enter `applySnapshot` and trigger
  UIKit's client assertion.
- Matrix HTML entities are decoded deterministically without asking WebKit to
  pump the main run loop during attributed-string construction.
- Identical timeline snapshots are suppressed before they reach the viewport,
  and native invalidations are coalesced into newest-state-only streams.
- Synthetic one-second timeline and room refreshes were removed; real native
  updates remain the authoritative source of live state.

## Composer Responsiveness

- The iOS composer no longer performs duplicate full-text layout measurement
  for each keystroke.
- Once a growing draft reaches its maximum visible height, append-only typing
  reuses that bounded height instead of repeatedly measuring the entire draft.
- Privacy-safe signposts cover composer layout and timeline snapshot work for
  future performance diagnosis without recording message content.

## Diagnostics and Validation

- The submitted TestFlight crash was symbolicated to UIKit's
  `BUG_IN_CLIENT_OF_DIFFABLE_DATA_SOURCE__APPLYING_SNAPSHOTS_REENTRANTLY_OR_ON_MAIN_AND_BACKGROUND_THREADS`
  assertion while Synara was rendering formatted room messages.
- Local validation passed 594 iOS unit tests with three expected skips, all 63
  iOS UI tests with fourteen opt-in live-environment skips, and a generic arm64
  Release build with notification-extension archive/linkage validation.
- The busy-room regression renders 300 formatted HTML messages, applies 60
  rapid live updates, types a paragraph, and verifies every character remains
  exact. It passed both the focused repeated run and the complete UI suite.
- Desktop type checking, linting, production build, 825 modernization tests,
  and repository/release policy gates also passed.

## What to Test

- Open a high-traffic room containing formatted messages and keep reading while
  new messages arrive; confirm the room remains stable.
- Type and edit a long paragraph while the room is actively updating; confirm
  input remains immediate and no characters are delayed or dropped.
- Submit any further TestFlight crash prompt so it can be compared with the
  resolved diffable-data-source signature.
