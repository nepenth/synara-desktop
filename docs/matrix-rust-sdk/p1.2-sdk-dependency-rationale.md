## Executive summary

Production Tauri crate `src-tauri` (`synara`) now declares **exact** Cargo
dependencies on `matrix-sdk` and `matrix-sdk-ui` version `=0.18.0` with
**`default-features = false`** and **no additional explicit feature list**.

This is **dependency presence + compile/link smoke only**:

- No production `Client` session is constructed at app startup.
- No login, sync, timeline subscription, or Matrix Tauri commands are wired.
- Product runtime Matrix behavior remains **only** `matrix-js-sdk` `42.0.0`
  in the frontend package.
- No dual-backend selector.

The scoped P1.2 criterion—**“Rust SDK is present but no production sync/login is
started”**—was evidenced at merge. It does not close the Phase 1 strict gate,
which remains `open` in [`program-status.md`](program-status.md).

### 2.3 Honest feature unification: `e2e-encryption`

Published `matrix-sdk-ui` `0.18.0` depends on:

```text
matrix-sdk = { version = "^0.18.0", default-features = false, features = ["e2e-encryption"] }
```

Cargo **feature unification** therefore enables `matrix-sdk/e2e-encryption` in
the production graph even though `synara` does **not** request that feature
directly and disables `matrix-sdk` defaults.

This is **expected and required** for `matrix-sdk-ui` timelines/crypto-aware UI
helpers. It is **not** a hidden kitchen-sink enablement of `sqlite`,
`bundled-sqlite`, `sso-login`, or `experimental-*`.

P1.2 does **not** start an encrypted session, open a crypto store, or run
sync — the feature only makes the crypto-capable SDK APIs available at compile
time.

## 4. Explicitly **not** enabled (deferred)

| Feature / capability | Why deferred |
|----------------------|--------------|
| `sqlite` / `bundled-sqlite` | Store selection lands with Client construction (later Phase 1/2). Avoid bundling native sqlite until needed. |
| `indexeddb` | Browser/wasm path; not desktop product store. |
| `rustls-tls` / other TLS feature toggles on matrix-sdk defaults | Not requested; HTTP stack still resolves transitively via SDK/reqwest graph under non-default feature set. Revisit if Client build fails without explicit TLS feature. |
| `sso-login` / `local-server` | Auth flows later; no login in P1.2. |
| `markdown`, `qrcode`, `socks`, `federation-api` | Not required for dependency acceptance. |
| `experimental-search`, `experimental-widgets`, `experimental-encrypted-state-events`, `experimental-element-recent-emojis`, `experimental-push-secrets`, `experimental-send-custom-to-device` | Program forbids ungate experimental Matrix features. |
| `unstable-msc*` / `uniffi` / `js` product paths | Not product desktop requirements for P1.2. |
| `automatic-room-key-forwarding` | Policy-sensitive crypto behavior; later gated decision. |
| Kitchen-sink “just in case” default features | Explicitly rejected to keep binary/link surface reviewable. |

## 9. Residual risks

1. **Compile-cost / CI time:** matrix-sdk + crypto (`aws-lc`, `vodozemac`)
   substantially enlarges `src-tauri` compile graph (P0.5 residual). Cache
   strategy still recommended; not fixed in P1.2.
2. **Linux / universal / notarization not re-proven** with SDK-linked product
   binary in this task (local macOS arm64 only).
3. **`e2e-encryption` always on** while `matrix-sdk-ui` is a direct dep — by
   design; binary will include crypto code paths even before product uses them.
4. **Store/TLS feature choices deferred** — first Client construction task must
   re-validate minimum features (`sqlite` etc.) rather than assuming defaults.
5. **MPL-2.0** transitive crates require ordinary MPL compliance awareness if
   those files are modified in-tree.
6. **No runtime security test** of Matrix crypto — out of scope; no session.
7. **Optional multi-target packages** (`matrix-sdk-sqlite`, `matrix-sdk-indexeddb`)
   may appear in lockfile/metadata for non-host targets; host `cargo tree -i`
   does not show them as active dependents. Do not treat as enabled product
   features without explicit feature flags.
