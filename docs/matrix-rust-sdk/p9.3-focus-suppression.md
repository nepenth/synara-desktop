## Summary

- `FocusState` explicitly distinguishes `Focused` from `Background`.
- `SuppressionPolicy` suppresses a notification candidate only while the app is
  focused on that candidate's room. A selected room does not suppress while the
  app is in the background.
- `BadgeCounter` provides session-generation-stamped total and per-room counts.
- Badge increments saturate at `u32::MAX`; decrements floor at zero.
- Room clear, full clear, and generation retirement keep aggregate state
  consistent. Generation retirement discards all counts.
- Marker: `matrix-notification-policy-p9.3`.

## Privacy and architecture

- State contains room identifiers, focus state, generations, and counts only.
- No tokens, secrets, recovery keys, event bodies, notification previews, or
  event plaintext are accepted or emitted.
- No DTO or IPC schema is added.
- The product runtime remains `matrix-js-sdk`; there is no dual-backend selector.
- Clean-break re-login remains the cutover policy.

## Out of scope

- Real window or application focus integration
- Native notification delivery
- Native dock, taskbar, or tray badges
- Production Tauri commands
- Changes to the P7.1 notification candidate index
