# D0.2 — native sync and room-list sole owner

## Outcome

Desktop password login and persisted-session restore now install one
`SyncServiceOwner` beside the managed Rust `Client` and start it immediately.
Logout stops that owner before clearing the in-memory session and persisted
session material. The webview never receives an access token, refresh token,
password, raw SDK room, or SDK vector diff.

This is a single-backend cutover for the desktop primary room list. When
`matrix_session_snapshot` reports `logged_in`, the `allRoomsAtom` binding polls
`matrix_room_list_snapshot` and does not attach Matrix JS SDK room listeners or
seed from `client.getRooms()`. Non-desktop use and desktop sessions not owned by
Rust retain the existing JS binding.

## Commands

- `matrix_sync_status` returns the privacy-safe `SyncReadinessSnapshot` for the
  active generation, or `unconfigured` when logged out.
- `matrix_room_list_snapshot` returns the generation, ordered joined-room IDs,
  and ordered minimal `RoomSummary` DTOs. The snapshot comes from
  `matrix-sdk-ui`'s all-rooms list with its joined filter and recency/name
  ordering.
- Existing `matrix_login_password` and `matrix_restore_session` now build and
  start sync before reporting success.
- Existing `matrix_logout` remotely logs out, stops sync, and then clears the
  native owner and persisted session material.

The localhost webview capability explicitly permits all six native Matrix
session/sync commands.

## Projection

The Rust projection currently includes room ID, cached display name, canonical
alias, MXC avatar URI, joined membership, direct/encrypted flags, bounded unread
and highlight counts, marked-unread state, and latest activity timestamp.
Favorite, low-priority, folder, join-rule, notification-mode, hero, and
tombstone fields remain unset until their dedicated native projections land.

The desktop binding polls once per second. A failed poll preserves the last
native snapshot; it never falls back to `client.getRooms()` while the native
session remains selected.

## Intentional residual breaks

- Timeline loading and room object hydration still depend on the legacy UI
  surface and may be empty or broken for IDs supplied by Rust. D0.3 owns the
  timeline cutover.
- Sending remains outside this slice and may be broken until D0.4.
- Invites, spaces/account-data relationships, typing, unread maps outside the
  primary ID list, and other shell-derived details are not made native here.
- This slice does not add `dual_backend`, a second sync loop, timeline/send
  IPC, crypto polish, mobile work, or L1 polish.
