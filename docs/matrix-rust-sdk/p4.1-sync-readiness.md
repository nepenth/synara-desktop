## Executive summary

P4.1 wraps `matrix_sdk_ui::sync_service::SyncService` for the historical partial path:

- Privacy-safe **`SyncReadiness`** phases (maps SDK `State` → product labels)
- Alignment with diagnostics **`SyncPhase`** for health snapshots
- Pure **reconnect decision table** (`Bootstrap` / `Recover` / `Pause` / `Shutdown`)
- **`SyncServiceOwner`** stamped with supervisor `session_generation`
- Build requires an **authenticated** `Client` (refuses empty session)
- Default **offline mode** enabled for transient outage recovery
- Guardrail: `SyncService::builder` only under `matrix/sync/`; raw `sync_once` still banned

**Out of scope:** production Matrix Tauri commands, room-list deltas (P4.2),
membership/unread (P4.3), dual-backend, live homeserver CI proof.

Product Matrix runtime remains **only** `matrix-js-sdk` until planned cutover.

## Readiness model

| `SyncReadiness` | SDK `State` | Product ready? |
|-----------------|-------------|----------------|
| `unconfigured` | (no service) | no |
| `idle` | `Idle` | no |
| `running` | `Running` | **yes** |
| `offline` | `Offline` | no (reconnecting) |
| `terminated` | `Terminated` | no (restartable) |
| `failed` | `Error(_)` | no (restart; diagnostic id only) |

`Running` is the first historical “sync ready” signal. Room-list completeness is
P4.2; this slice only proves the owner loop is live.

---

## Reconnect policy (pure)

| Intent \ Readiness | Unconfigured | Idle/Terminated/Offline | Running | Failed |
|--------------------|--------------|-------------------------|---------|--------|
| Bootstrap | None | Start | None | Start |
| Recover | None | Start | None | **Restart** |
| Pause | None | None | Stop | None |
| Shutdown | None | None | Stop | None |
| Observe | None | None | None | None |
