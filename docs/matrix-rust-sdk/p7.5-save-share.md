## Summary

- `matrix::media_export` models Save, Share, Open, and Drag intents.
- `ExportJob` contains only an id, kind, opaque media handle id, optional room
  id, and lifecycle state.
- Lifecycle: Pending → Running → Succeeded | Failed | Cancelled.
- Generation retirement cancels pending and running work; terminal jobs can be
  pruned without touching media.
- Opaque handles and room ids are redacted from `Debug`. Errors contain only
  fixed privacy-safe diagnostic ids.
- Marker: `matrix-media-export-p7.5`.

## Data boundary

The queue never accepts or stores ciphertext or plaintext media bytes. It owns
no destination path and performs no filesystem calls. A future platform adapter
may resolve the opaque media handle and hold an OS path/handle outside this
state machine; any exposed path metadata must be limited to a basename.

## Out of scope

- OS save dialogs, share sheets, open handlers, or drag-and-drop integration
- Matrix media download/decryption
- IPC command registration or DTO serialization
- Token migration, dual-backend behavior, or matrix-js-sdk cutover
