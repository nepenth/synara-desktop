# D0.6 — matrix-js-sdk product import burn-down

Status: native desktop core clean; approved non-zero residual plateau.

## Result

The exact post-change inventory under `synara/src` is **232 files / 292 import
statements** referencing `matrix-js-sdk` or one of its subpaths:

```bash
rg -l "(?:from\\s+['\"]matrix-js-sdk|import\\s*\\(['\"]matrix-js-sdk|require\\(['\"]matrix-js-sdk)" \
  synara/src | wc -l
# 232

rg -n "(?:from\\s+['\"]matrix-js-sdk|import\\s*\\(['\"]matrix-js-sdk|require\\(['\"]matrix-js-sdk)" \
  synara/src | wc -l

```

This PR removes **0 importer files / 0 import statements**. That is an honest
plateau, not a claim of zero. The high-value change is that a native desktop
session no longer enters the legacy `ClientRoot` path that constructs and
starts a live matrix-js-sdk client.

On native desktop, password login and startup restore now install only a
token-free native identity (`userId`, `deviceId`, `homeserverUrl`) as routing
state. The authenticated route mounts a small native shell backed by the
existing Rust IPC for room list, opened-room timeline, text send, crypto status,
and logout. It does not mount the matrix-js-sdk provider, server-config loaders,
legacy room providers, or non-UI JS sync features.

Browser sessions and pre-existing token-bearing legacy sessions retain the
existing product UI. There is no backend selector, no `dual_backend`, and no
token or key is added to IPC.

## Removed this PR

No import statement is labeled “removed this PR.” The following live native
ownership residuals are removed:

- Native login completion now records the non-secret Rust identity so the
  authenticated router can enter without a JavaScript `Session`.
- Desktop startup invokes `matrix_restore_session` before mounting the app and
  records only the returned non-secret identity. Legacy token-store bootstrap
  and service-worker credential push are skipped when native restore succeeds.
- The authenticated router recognizes either a native identity or a legacy
  JavaScript session.
- `ClientRoot` selects the native shell before any legacy client hooks run.
  Consequently native sessions do not call `initClient`, `createClient`,
  `initRustCrypto`, or `startClient`.
- The native shell reads the Rust room-list/timeline snapshots, sends plain text
  through `matrix_send_text`, displays the existing native crypto status, and
  logs out through `matrix_logout`. Logout also clears any stale legacy session
  stores so routing cannot silently re-enter the JavaScript client.
- Restore failure clears stale native routing state and fails closed to the
  unauthenticated/legacy decision; it does not synthesize a token-bearing
  session or fall back after selecting native ownership.

## Guardrails and dependency decision

The P1.6 allowlist remains correct at **220 production paths**. All 220 still
import matrix-js-sdk, and the remaining 12 importer files are tests. This PR
adds no new matrix-js-sdk importer and does not loosen the allowlist or
dual-backend guardrail.

The `matrix-js-sdk` npm dependency must remain. The approved residual includes
browser authentication and client bootstrap, calls/RTC, settings, media,
devices/verification, rich timelines and sends, plus pervasive SDK model types.
Deleting the package now would break those retained surfaces and would make the
ledger false.
