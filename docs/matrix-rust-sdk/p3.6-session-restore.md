## Executive summary

Implements **session restore + identity-scoped account switch structure** for
the Matrix Rust foundation (plan Phase 3 / P3.6), building on P3.5:

- Load sealed v1 envelope from `SessionMaterialVault`
- Bind user id + homeserver to `AccountIdentity`
- Install via `Client::restore_session` (Matrix native auth only)
- Privacy-safe `SessionRestoreOutcome` (no tokens)
- Identity-scoped vault keys enable multi-account restore without dual-backend
- Guardrail: `.restore_session` allowed **only** under `matrix/lifecycle/`

**Out of scope:** production Tauri Matrix commands, dual-backend, live sync
(P4.x), OAuth restore (P3.3), elaborate JS→Rust session migration (clean-break
approved), remote logout orchestration beyond existing P2.6 hooks.

Product Matrix runtime remains **only** `matrix-js-sdk` until planned cutover.

## 3. Composition (dogfood path)

```text
build_unauthenticated_client(config for AccountIdentity)   # P2.3
  → restore_session_from_vault(client, identity, vault)    # P3.6
       → load sealed blob (P3.5)
       → bind user/homeserver
       → Client::restore_session(MatrixSession)
  → (later) sync / room list                               # P4.x
```

Login path remains:

```text
login_with_password/token → optional persist_session_after_login  # P3.2 + P3.5
```

Account switch: choose another `AccountIdentity`, open **that** account's store
paths, restore **that** vault entry. Never run two live Matrix clients for the
same session; never introduce a JS/Rust selector.
