> **Pure harness only.** This foundation projects bounded call summaries for
> product UI. It does not start MatrixRTC or enable experimental widgets.

## Summary

- `CallMember`: Matrix user localpart, `Join | Leave | Invite`, and an optional
  opaque device label. Full MXIDs are rejected.
- `CallSessionSummary`: room id, call id, member rows, and
  `Idle | Ringing | Active | Ended`.
- `CallStateIndex`: generation-stamped upsert, member update, room listing, and
  retirement.
- Members are unique by user localpart and kept in stable localpart order.
- Each session is capped at `MAX_CALL_MEMBERS` (256). Replacing an existing
  member remains allowed at the cap.
- Marker: `matrix-call-state-p10.4`.

## Privacy boundary

The projection contains no access tokens, recovery keys, cryptographic
material, event plaintext, or media bytes. `CallMember`, `CallSessionSummary`,
and `CallStateIndex` intentionally do not implement `Debug` or `Display`.
Errors expose static diagnostic ids only. Device labels are opaque,
presentation-only input and are never interpreted as device ids or credentials.

## Ordering and lifecycle

Session members are sorted by user localpart on full upsert and maintained in
that order on member updates. Sessions returned by `list_room` are scoped to
the requested room and ordered by call id. `retire_generation` updates the
session generation and wipes all projected call state for logout/account
switch safety.

## Out of scope

- Live MatrixRTC or Matrix Rust SDK call integration
- Element Call UI
- `postMessage` bridges
- Experimental feature flags or widgets
- Production Tauri commands
- Dual-backend behavior; the product remains on `matrix-js-sdk` until cutover
