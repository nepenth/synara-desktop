## Executive summary

This task implements **destructive lifecycle operations** for the Matrix Rust
foundation (plan Phase 2 / P2.6, §8.3, P0.7, `D-LOGOUT-WIPE`):

- **Logout** path: drop client handle, retire generation-stamped tasks, clear
  session material hooks (harness/mock keyring) — **without** deleting stores
- **Local wipe** of **exact** per-account store paths only
  (`state` / `crypto` / `cache` / `media` under the account segment)
- **Failed-store recovery** that surfaces `StoreCorrupt` / `StoreUnavailable` /
  `StoreLocked` and **never** auto-deletes; explicit wipe is a separate command
- Exact-target safeguards unit tests (wrong path refused; sibling untouched;
  ensure/open failure ≠ wipe)
- Integration with `MatrixSupervisor` `BeginWipe`/`CompleteWipe`,
  `TaskSupervisor` retire, optional `MatrixMetrics` record

**Out of scope:** production Tauri Matrix product commands, live network
login/sync product path, dual-backend, remote logout product copy (**P3.8**).

Product Matrix runtime remains **only** `matrix-js-sdk`.

## 3. Logout vs wipe (`D-LOGOUT-WIPE`)

| Action | Supervisor | Client handle | Tasks | Session material | Store dirs | Store key |
|--------|------------|---------------|-------|------------------|------------|-----------|
| **Logout** | `BeginStop` → `CompleteLogout` | drop | retire via generation | clear | **intact** | intact |
| **Local wipe** | `BeginWipe` → disk wipe → `CompleteWipe` | drop | retire | clear | **destroyed** (exact account only) | clear |

The local-wipe row records the original intended end state, not safe operation
ordering. Current code performs destructive deletion before client/task teardown;
it must not be used as acceptance evidence until REV-001 is resolved.

Crash recovery / open failure **must not** auto-wipe (P0.7).

---

## 4. Exact-target wipe safeguards

Wipe is allowed only after `WipeTarget::resolve(app_data_root, identity)`:

1. Identity fully validated (`AccountIdentity`)
2. `app_data_root` absolute, non-empty, no `..` components
3. Paths derived via P2.2 `StorePaths::derive` (segment traversal rejected)
4. Account root is **exactly one** normal component under
   `{app_data_root}/matrix/`
5. Children are **exactly** the known subdirs under account root
6. Refuse wipe of matrix root, app data root, sibling accounts, or arbitrary paths
7. Refuse symlink wipe targets
8. Idempotent when dirs already absent

`assert_exact_account_root` / `assert_path_is_wipe_allowed` refuse wrong paths
before any deletion.

## 5. Failed-store recovery policy

```text
StoreFailure(Corrupt | Unavailable | Locked)
  → RecoveryAction::SurfaceOnly { category, diagnostic_id, store_status }
  → metrics: set_store_status + record_store_open_failure + record_error
  → optional supervisor.fail(...)
  → requests_wipe() == false  // always
```

Explicit wipe requires a separate deliberate call to `perform_local_wipe` with a
resolved `WipeTarget`.
