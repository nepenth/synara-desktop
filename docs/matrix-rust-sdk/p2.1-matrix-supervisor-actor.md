## Executive summary

This task implements the **Matrix supervisor actor foundation**: a pure
lifecycle state machine with **session-generation isolation** and a **sole
client-handle construction path** for the eventual single-owner Matrix Rust
SDK client (plan Phase 2 / §3.6).

**In scope:**

- Lifecycle states (via `dto::SessionLifecycle`): `empty`, `opening`,
  `authenticating`, `restoring`, `syncing`, `ready`, `stopping`,
  `logged_out`, `failed`, `wiping`
- Pure transition table (`SupervisorCommand` → next state + `TransitionEffect`)
- Actor shell (`MatrixSupervisor`) with generation + opaque handle slot
- Abstract `ClientHandle` / `ClientFactory` (harness stubs only — **not**
  `matrix_sdk::Client`)
- Generation bumps on `BeginOpen`, `CompleteLogout`, and `CompleteWipe`
- Unit tests for legal/illegal transitions, sole construction path, leak-free
  open/logout/wipe cycles
- Design note + machine twin

**Out of scope (explicit):**

- Real `matrix_sdk::Client` builder / network login/sync — **P2.3**
- Store paths and encryption keys — **P2.2**
- Async task supervision / cancellation joins — **P2.4**
- Diagnostics/health metrics product surface — **P2.5**
- Destructive lifecycle product I/O (real wipe/logout against disk) — **P2.6**
- Production Matrix Tauri commands / frontend cutover
- Dual-backend / SDK selector
- Network login/sync against homeservers in unit tests

Product Matrix runtime remains **only** `matrix-js-sdk`.

**Client handle deferred:** P2.1 uses an opaque `ClientHandle` trait + test
factories so the supervisor can prove sole-owner install/drop cycles without
constructing a real SDK client. P2.3 attaches the production builder under this
supervisor only.

## 2. States

Wire-identical to `dto::SessionLifecycle` (`snake_case` on wire):

| State | Meaning |
|-------|---------|
| `Empty` | No session ownership |
| `Opening` | Bootstrap / path prep |
| `Authenticating` | Interactive auth path |
| `Restoring` | Restore persisted native session |
| `Syncing` | Initial / catch-up sync |
| `Ready` | Session live; publish allowed |
| `Stopping` | Teardown in progress |
| `LoggedOut` | Logout complete; wipe still available |
| `Failed` | Epoch failure; open/reset/wipe |
| `Wiping` | Local wipe in progress |

`may_publish(gen)` is true only for `Syncing`/`Ready` **with** an installed
handle and matching live generation.

---

## 3. Commands

| Command | Role |
|---------|------|
| `BeginOpen` | Empty/LoggedOut/Failed → Opening (**bumps generation**) |
| `BeginAuthenticate` / `BeginRestore` | Opening → auth or restore (exclusive) |
| `InstallClient` | Sole handle construction via `ClientFactory` |
| `BeginSync` / `MarkReady` | → Syncing → Ready (require installed client) |
| `BeginStop` / `CompleteLogout` | → Stopping → LoggedOut (drop client, **bump**) |
| `BeginWipe` / `CompleteWipe` | → Wiping → Empty (drop client, **bump**) |
| `Fail` | → Failed (drop client; no bump) |
| `ResetEmpty` | Failed/LoggedOut → Empty |

Illegal transitions return `TransitionError` / `SupervisorError` without
mutating lifecycle when the pure resolve fails.

---

## 4. Generation isolation

| Event | Bump? |
|-------|-------|
| `BeginOpen` | yes (new epoch) |
| `CompleteLogout` | yes (retire publishers) |
| `CompleteWipe` | yes |
| `Fail` | no (next `BeginOpen` bumps) |
| other | no |

Fresh supervisor: `session_generation = 0`, lifecycle `Empty`.

Aligned with P0.7 `D-NO-DUAL-BACKEND` / no unsafe token reuse into a fresh
crypto store: logout and wipe retire the generation so restored epochs cannot
accept stale publishers.

---

## 5. Sole construction path

```
MatrixSupervisor::apply_with_factory(InstallClient, &factory)
  → ClientFactory::build(generation)
  → at most one ClientHandle installed
```

- Second `InstallClient` → `ClientAlreadyPresent`
- `BeginSync` / `MarkReady` without handle → `ClientMissing`
- `NullClientFactory` refuses construction (default until P2.3)
- `TestClientFactory` / `FailingClientFactory` for harnesses only
- **No** `matrix_sdk::Client::builder` under `src-tauri/src/matrix/`

---

## 6. Primary flows (tested)

```
Empty → BeginOpen → Opening → BeginAuthenticate → Authenticating
  → InstallClient → BeginSync → Syncing → MarkReady → Ready
  → BeginStop → Stopping → CompleteLogout → LoggedOut  (gen++)

Empty → BeginOpen → Opening → BeginRestore → Restoring
  → InstallClient → BeginSync → Syncing → MarkReady → Ready
  → BeginWipe → Wiping → CompleteWipe → Empty  (gen++)
```

Logout ≠ wipe (`D-LOGOUT-WIPE`): LoggedOut can still `BeginWipe`.
