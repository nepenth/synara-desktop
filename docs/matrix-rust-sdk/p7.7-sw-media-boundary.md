## Boundary

The native Rust host is the sole allowed owner of Matrix authentication and
sensitive media capabilities. A service worker must not:

- store Matrix access or refresh tokens;
- decrypt encrypted Matrix media; or
- retain a long-lived MXC cache containing secrets.

`matrix::media_boundary` records these restrictions as pure `BoundaryRule`
values. `assert_owner` rejects service-worker ownership and fails closed for
capabilities absent from the inventory. Its error contains only a fixed
category and never includes the caller-provided capability string.

## Runtime state

This is a Rust-side foundation guard only. It does not remove or alter the
existing JavaScript service worker. The product remains on `matrix-js-sdk`
until cutover, and there is no dual-backend mode.

At cutover, the native host must perform authenticated media fetch,
decryption, and secret-bearing cache management. Web/UI surfaces may receive
only safe handles and metadata across the existing IPC boundary.

## Out of scope

- deleting service-worker JavaScript;
- enabling Matrix Rust SDK media network operations;
- changing the active product backend;
- introducing a dual-backend selector; or
- carrying tokens, recovery keys, event plaintext, or media bytes in DTOs,
  diagnostics, logs, `Debug`, or `Display`.

## Acceptance

- the default inventory contains the three forbidden service-worker
  capabilities;
- every default rule allows `HostNative`;
- every default rule rejects `ServiceWorkerForbidden`;
- unknown capabilities fail closed without echoing their input; and
- the module marker is included in the Matrix marker union.
