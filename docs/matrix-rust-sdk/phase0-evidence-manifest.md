This is the semantic twin of the JSON. R0.2 establishes evidence completeness
and execution readiness only. It cannot accept P0.1–P0.7, change strict Phase 0
criteria, approve a deferral, or close Phase 0. Only an independent R0.8 review,

## Subject and lifecycle contract

The repository is `nepenth/synara-desktop`, the program branch is
`feature/matrix-rust-sdk-full-replacement`, the shipping desktop remains
`matrix-js-sdk 42.0.0`, and linked `matrix-sdk`/`matrix-sdk-ui 0.18.0` is
nonshipping. No production dual backend exists.

Evidence states are `planned`, `pending`, `produced_pending_review`, `accepted`,
`rejected`, `failed`, `blocked`, `deferred`, `stale`, and `expired`. Only
`accepted` can satisfy a gate. Residual states are `pending`, `blocked`,
`decision_required`, `deferred_pending_approval`,
`approved_bounded_deferral`, `resolved`, `reopened`, and `rejected`. Every state
other than accepted evidence or an R0.8-reviewed bounded deferral keeps the
applicable gate open.

Produced evidence is bound to a full commit SHA and either an immutable PR/run/job
URL or a repository path at that commit. Missing, rejected, failed, blocked,
deferred, stale, expired, or merely produced evidence cannot silently pass.
Live/performance evidence expires after its stated UTC interval; ephemeral
artifacts expire with their source; toolchain evidence refreshes on toolchain or
lock changes. A changed candidate, SDK, producer, fixture, platform, Synapse
image, or criterion makes affected evidence stale and requires a new record.

Deferrals never equal acceptance. `approved_bounded_deferral` requires a unique
ID, independent approver, immutable Synara PR/review/commit reference, bounded
rationale, risk, compensating control, UTC expiry, and reopen criteria. The
implementer, evidence producer, and row owner cannot self-accept.

## Credential contract

`SYNARA-DISPOSABLE-RUNTIME-SECRETS-V1` is the only disposable-test secret
mechanism. `scripts/synapse-integration.sh` uses umask `077` and writes generated
runtime material only below `integration/synapse/runtime`; account passwords and
access tokens exist only in process memory. Stable account localparts and device
display names are identities, not credentials. Passwords, tokens, registration
secrets, signing keys, and database passwords must never be committed, embedded,
printed, logged, or attached. Evidence contains only safe phase/count/error/exit
and cleanup data. Reset destroys runtime files, stores, media, volumes, database,
and sessions; every rerun rotates credentials.
