## Executive summary

This task implements the **task supervision and cancellation foundation** (plan
Phase 2 / P2.4 / §3.6):

- `TaskSupervisor` registry for kinds: `sync`, `listener`, `upload`, `search`,
  `generic`
- Register / spawn / cancel / join APIs with **session-generation stamping**
- On generation bump (logout / wipe / fail-reopen): cancel + await drop of tasks
  for the old generation; refuse stale-generation task results
- Deterministic unit tests: race cancel, double-cancel, stale generation
  isolation, leak-free open/close cycles
- Light composition with `MatrixSupervisor` via
  `tasks::follow_supervisor_generation` (async; actor stays pure/sync)

**Out of scope (explicit):**

- Production login/sync cutover / second product sync loop
- Dual-backend / SDK selector
- Production Matrix Tauri commands
- Diagnostics/health product surface — **P2.5**
- Destructive lifecycle disk I/O — **P2.6**
- Live homeserver network in unit tests

Product Matrix runtime remains **only** `matrix-js-sdk`.

## 2. API surface

### Kinds (`TaskKind`)

| Kind | Wire name | Intended work |
|------|-----------|---------------|
| `Sync` | `sync` | Sync / sync-service loop |
| `Listener` | `listener` | Room/timeline/account-data listeners |
| `Upload` | `upload` | Media / attachment upload |
| `Search` | `search` | Message / room search |
| `Generic` | `generic` | Harness / unclassified short work |

### Core type: `TaskSupervisor`

| Method | Role |
|--------|------|
| `new()` | Empty registry, live generation `0` |
| `live_generation` / `set_live_generation` / `bump_generation` | Generation bookkeeping |
| `register(kind, generation)` | Pure placeholder entry (no runtime future) |
| `spawn(kind, generation, fut)` | Tokio-spawn unit future; refuses stale gen |
| `cancel(id)` | Abort if running; **idempotent** double-cancel |
| `cancel_generation` / `cancel_all` | Bulk cancel requests |
| `join(id)` | Await + remove from registry |
| `cancel_and_join(id)` | Cancel then join one task |
| `retire_generation(gen)` | Cancel + join all tasks for a generation |
| `retire_stale()` | Cancel + join all tasks ≠ live generation |
| `shutdown_all()` | Full registry drain (open/close cycles) |
| `accept_result(generation)` | Refuse superseded session generation |
| `accept_task_result(id)` | Refuse if task’s stamp ≠ live generation |
| counters / `list` / `get` | Diagnostics helpers (no secrets) |

### Bridge (`tasks::bridge`)

| Function | Role |
|----------|------|
| `follow_supervisor_generation(tasks, supervisor)` | Set live gen from actor; `retire_stale` |
| `mirror_generation(tasks, supervisor)` | Copy gen without retiring (fixture setup) |

Call `follow_supervisor_generation` **after** generation-bumping commands
(`BeginOpen`, `CompleteLogout`, `CompleteWipe`). Fail alone does not bump
(P2.1); reopen via `BeginOpen` does.

---

## 3. Generation isolation

```
spawn/register  →  stamp = live_generation only
accept_result   →  Err(StaleGeneration) if observed ≠ live
bump_generation →  live++
retire_stale    →  cancel+join all tasks with stamp ≠ live
```

Aligned with P2.1:

| Lifecycle event | Generation bump? | Task action |
|-----------------|------------------|-------------|
| `BeginOpen` | yes | follow → retire prior epoch tasks |
| `CompleteLogout` | yes | follow → retire |
| `CompleteWipe` | yes | follow → retire |
| `Fail` | no | follow is no-op until reopen |
| other | no | — |

Stale task completion paths must call `accept_result` / `accept_task_result`
before publishing into UI/IPC (later phases).

---

## 4. Composition model

`MatrixSupervisor` remains a pure synchronous state machine (P2.1). Async cancel
and join live in standalone `TaskSupervisor` owned by `matrix::tasks`.

```
MatrixSupervisor.apply(CompleteLogout)  // bumps gen, drops client handle
tasks::follow_supervisor_generation(&mut tasks, &supervisor).await
  → set_live_generation(supervisor.session_generation())
  → retire_stale()  // cancel + await old tasks
```

Future product wiring (P3+/cutover) holds both under the single Matrix owner;
this task does **not** start production sync or register Tauri commands.
