## Executive summary

This task implements the **privacy-filtered Matrix diagnostics and health model**
(plan Phase 2 / P2.5):

- Health snapshot types for lifecycle, sync, queue, store, tasks, and errors
- Mutable `MatrixMetrics` collector with supervisor + task-supervisor bridges
- Desktop-compatible projection onto `desktop_logging` allowlisted fields
- Secret redaction helpers and fixture tests proving tokens, recovery keys,
  MXIDs, homeserver URLs, event bodies, and media blobs never appear in
  diagnostic output

**Out of scope:** production login/sync loops, product Tauri Matrix commands,
dual-backend, automatic diagnostic upload, live homeserver network, destructive
wipe (P2.6).

Product Matrix runtime remains **only** `matrix-js-sdk`.

## 3. Metric surface

### Lifecycle (`LifecycleHealth`)

| Field | Meaning |
|-------|---------|
| `state` | `SupervisorState` wire name |
| `session_generation` | Live session generation (**not** tokens) |
| `has_client` / `live_handles` | Handle presence gauges |
| `installed_total` / `shutdown_total` | Leak-check counters from actor |
| `last_failure_category` | `MatrixIpcErrorCategory` wire name |
| `last_failure_diagnostic_id` | Opaque static diagnostic code only |

### Sync (`SyncHealth`)

| Field | Meaning |
|-------|---------|
| `phase` | `idle` / `catching_up` / `live` / `reconnecting` / `paused` / `failed` |
| `transition_count` | Phase change counter |
| `recovery_requests` | Sync recovery request count |
| `last_duration_ms` | Last observed cycle duration |

### Queue (`QueueHealth`)

| Field | Meaning |
|-------|---------|
| `depth` / `max_depth` | Current and high-water queue depth |
| `soft_max` | Soft bound (`MAX_STREAM_QUEUE_DEPTH`) |
| `dropped` / `coalesced` | Backpressure counters |

### Store (`StoreHealth`)

| Field | Meaning |
|-------|---------|
| `status` | `unknown` / `ready` / `locked` / `unavailable` / `corrupt` / `missing` |
| `state_ready` / `crypto_ready` / `cache_ready` / `media_ready` | Subsystem readiness booleans |
| `open_failures` | Open failure count (**never** auto-wipes) |

### Tasks (`TaskHealth`)

| Field | Meaning |
|-------|---------|
| `live_generation` | Task supervisor live generation |
| `registered` / `running` | Current registry gauges |
| `spawned_total` / `joined_total` / `cancelled_requests` | Lifetime counters |
| `registered_by_kind` | Counts for sync / listener / upload / search / generic |

### Errors (`ErrorHealth`)

| Field | Meaning |
|-------|---------|
| `total` | Classified error total |
| `by_category` | Per-`MatrixIpcErrorCategory` counts |
| `last_category` / `last_diagnostic_id` | Last failure (privacy-safe id only) |

## 4. Desktop compatibility

Projection (`project_health_to_desktop`) emits four `session`-category records:

| Event | Namespace |
|-------|-----------|
| `session.lifecycle` | lifecycle gauges |
| `sync.metrics` | sync phase / duration |
| `matrix-store.health` | store readiness |
| `matrix-client.health-snapshot` | tasks + queue + last error |

Fields are restricted to desktop allowlist subsets (`generation`, `queueDepth`,
`hasSession`, `syncState`, `errorType`, `backend`, …). No free-form secrets,
MXIDs, URLs, or paths.

Full snapshots remain available via serde for harness assertions and future
support tooling (P13.8).

---

## 5. Privacy invariants

1. **No tokens** — access/refresh/session tokens never stored or projected.
2. **No recovery secrets** — recovery keys / secret-storage material rejected.
3. **No store keys** — only readiness booleans, never passphrase/hex keys.
4. **No event plaintext / media bytes / raw push payloads**.
5. **No MXIDs / room / event IDs / homeserver URLs** in free-form fields.
6. **Diagnostic ids** must pass `safe_diagnostic_label` (short opaque codes).
7. **Redaction fixtures** prove hostile JSON is detected and cleaned.
