## Executive summary

This task implements the **privacy-filtered Matrix diagnostics and health model**
(plan Phase 2 / P2.5):

- `MatrixMetrics` collector under `src-tauri/src/matrix/diagnostics/`
- `MatrixHealthSnapshot` covering lifecycle, sync, queue, store, tasks, errors
- Task counter export from P2.4 `TaskSupervisor` (`spawned` / `joined` /
  `cancelled` / per-kind registered counts)
- Supervisor observation via `MatrixSupervisor::snapshot` + install/shutdown totals
- Desktop-compatible projection (`session` category + allowlisted fields /
  event namespaces already accepted by `desktop_logging`)
- Redaction helpers + fixture tests proving tokens, MXIDs, URLs, bodies, and
  ciphertext never appear in health exports

**Out of scope:** production login/sync loops, wiring `desktop_record_diagnostic`
from live product paths, dual-backend, production Matrix Tauri commands,
destructive wipe (**P2.6**).

Product Matrix runtime remains **only** `matrix-js-sdk`.

## 3. Health model surface

| Slice | Contents (privacy-safe) |
|-------|-------------------------|
| **Lifecycle** | state enum string, session generation, has_client, handle counts, last failure category + diagnostic_id |
| **Sync** | phase (`idle`/`catching_up`/`live`/`reconnecting`/`paused`/`failed`), transition + recovery counts, last duration ms |
| **Queue** | depth, max depth, soft max (`MAX_STREAM_QUEUE_DEPTH`), dropped, coalesced |
| **Store** | status enum (unknown/ready/locked/unavailable/corrupt/missing), per-subdir readiness flags, open failure count — **no paths, no keys** |
| **Tasks** | live generation, registered/running, spawned/joined/cancelled totals, counts by `TaskKind` |
| **Errors** | total, per-`MatrixIpcErrorCategory` counts, last safe diagnostic_id |

**Never present:** access/refresh tokens, recovery keys, store keys, MXIDs,
room/event IDs, homeserver URLs, message bodies, ciphertext, absolute paths.

---

## 4. Desktop diagnostics compatibility

Projected records use:

| Field | Value |
|-------|--------|
| category | `session` |
| events | `session.lifecycle`, `sync.metrics`, `matrix-store.health`, `matrix-client.health-snapshot` |
| numbers | `generation`, `queueDepth`, `coalescedCount`, `eventCount`, `retryCount`, `waiterCount`, `totalSize`, `durationMs` |
| booleans | `hasSession`, `success`, `available`, `nativeStoreConfigured`, `nativeStoreAvailable`, `nativeStoreError` |
| labels | `phase`, `status`, `backend`, `errorType`, `reason`, `syncState`, `persistence`, `queueState` |

These namespaces and field keys are already accepted by
`src-tauri/src/desktop_logging.rs` / `clientDiagnostics.ts`. Live bridge write
to the diagnostics store is deferred (product capture opt-in path).

---

## 5. Invariants

1. **Counts and enums only** on the health wire — no free-form secret strings.
2. **Unsafe diagnostic_id dropped** — only `safe_diagnostic_label` values retained.
3. **Desktop projection allowlist** — every projected field key is on the
   documented number/boolean/label lists.
4. **Redaction fixtures prove absence** of tokens / MXIDs / URLs / bodies.
5. **No dual-backend**; no production Matrix Tauri commands; no login/sync.
