## Executive summary

This task adds **CI-enforced architectural guardrails** for the Matrix Rust SDK
full replacement (plan P1.6). Two complementary scripts enforce:

1. **Allowlist / wire / HTTP / versioned IPC**
   (`scripts/matrix-rust-p1.6-guardrails.mjs`)
2. **Dual-backend ban, no production Client under `matrix/`, no premature
   Matrix Tauri commands** (`scripts/check-matrix-rust-sdk-guardrails.mjs`)

**In scope:** guardrail scripts, committed JS SDK importer allowlist, unit
tests with prohibited fixtures, npm + CI wiring, design note.

**Out of scope:**

- Production Matrix login/sync/Client construction
- Full removal of existing `matrix-js-sdk` product usage (still sole runtime;
  full ban waits for plan Phase 11/14 cutover)
- Phase 2 supervisor / secure storage
- Merging to `main`

Product Matrix runtime remains **only** `matrix-js-sdk` until cutover.

## 2. Rules

| Rule id | Surface | Forbidden |
|---------|---------|-----------|
| `js-sdk-hard-ban-wire` | `matrix-ipc/**`, `matrix-dto/**` | Any `matrix-js-sdk` import |
| `js-sdk-new-importer` | other `synara/src/**` production | Import not on committed allowlist |
| `raw-matrix-http` | product runtime (non-exception) | `/_matrix/` outside REST exceptions |
| `sdk-types-in-wire` | Rust/TS DTO+IPC modules | `matrix_sdk` / `ruma` / JS SDK types |
| `unversioned-ipc` | IPC modules / envelopes | Missing `protocolVersion` / constant |
| `no-production-matrix-client-in-matrix-module` | `src-tauri/src/matrix/**` (non-test) | `Client::builder`, login/sync/restore APIs |
| `no-dual-backend-selector` | `synara/src/**`, `src-tauri/src/**` (non-test) | `MatrixBackend`, selector flags |
| `no-matrix-product-tauri-commands` | `src-tauri/src/lib.rs` invoke_handler | Any `matrix_*` command registration |

**Explicitly allowed:**

- Product `matrix-js-sdk` usage on the **allowlist** (baseline at P1.6 start; ratchet only shrinks)
- `matrix_sdk_link_smoke` (outside `matrix/dto` + `matrix/ipc`) for compile-only SDK linkage
- Doc comments that *mention* SDK names (comments stripped before scanning)
- Existing desktop REST exceptions (`sw.ts`, `cs-api.ts`)
- Test paths (`/__tests__/`, `tests.rs`, `*_synapse_proof.rs`, `*.test.*`) for
  opt-in disposable-Synapse live proofs that need `sync_once` / HTTP helpers
- `reqwest::Client::new()` (HTTP helper; not matrix-sdk `Client` construction)

## 3. CI integration

1. `npm run check:matrix-boundaries` — legacy `/_matrix/` REST exceptions, then
   both P1.6 scripts (allowlist/wire + dual-backend/Client/Tauri).
2. `npm run check:matrix-rust-guardrails` — both P1.6 scripts only
   (`matrix-rust-p1.6-guardrails.mjs` then `check-matrix-rust-sdk-guardrails.mjs`).
3. Unit tests: `node --test scripts/__tests__/*.test.mjs` (includes both P1.6
   test files).
4. CI `validate` job runs the dedicated guardrails step and the script tests.

Acceptance: representative prohibited fixtures in unit tests **must fail** the
checker; the live repository **must pass**.
