# Matrix Rust SDK 0.19.1: capabilities and Synara adoption

Synara's shared Rust core (`crates/synara-core`) pins `matrix-sdk` and
`matrix-sdk-ui` 0.19.1 (`MATRIX_SDK_PIN_VERSION`). This table replaces the
0.18.0 feature and gap analysis, which described the SDK before the migration
landed. It lists the 0.19.1 capabilities Synara uses, or deliberately does not,
and where. Review IDs (S1–S20, L*, T*) refer to the October 2026 second-opinion
review. Update a row when an adoption changes.

Status: **Adopted** (SDK route in production), **Partial** (SDK route plus a
Synara layer or a remaining raw request), **Not adopted** (planned or
deliberately declined; see the note).

## Raw HTTP outside the SDK

`scripts/check-matrix-boundaries.mjs` flags `reqwest`, `http_client()` and
`"/_matrix/"` literals in `crates/**` and `src-tauri/**` outside test code. The
remaining exceptions are named there with their reasons: size-capped media
(`app/media/bounded.rs`) and the redirect-free reqwest client handed to the SDK
for auth probes (`app/client_builder/open.rs`). Typed `client.send(request)`
calls (aliases, `joined_members` fallback, `/notifications`, `/search`,
`timestamp_to_event`, push rules) go through the SDK's HTTP client and are not
flagged.

## S10: why threading support stays off

With `ThreadingSupport::Enabled { with_subscriptions: false }`, 0.19.1 changes
one thing: `RoomReadReceiptEventFilter` drops in-thread events from the room's
client-side unread, notification and mention counts. Timelines, receipts,
latest events and the thread list are unaffected, and thread subscriptions
stay off. Synara has no room-level thread indicator, and Synapse's simplified
sliding sync sends no server counts, so a reply or a mention inside a thread
would no longer badge its room. Instead, an automatic read at the live bottom
also acknowledges newer thread replies whose roots the timeline shows, which
clears the room once the user has seen those thread summaries.
