## Summary

- `NotificationCandidateStream` is a pure, session-generation-scoped harness.
- `Candidate` contains only `room_id`, `event_id`, `kind`, `suppressed`, and a
  stream-assigned monotonic `sequence`.
- `CandidateKind` supports `Message`, `Mention`, `Invite`, and `Other`.
- `push` rejects duplicate room/event keys; `upsert` replaces and moves a key
  to the newest sequence.
- `mark_suppressed` changes only the suppression hook and preserves ordering.
- `list_recent(cap)` returns the newest bounded window in chronological order.
- The stream retains at most 128 candidates and drops the oldest on overflow.
- `retire_generation` wipes all candidates and resets sequence allocation.
- Marker: `notification-stream-p9.2`.

## Privacy boundary

The stream has no title, body, preview, ciphertext, token, secret, recovery key,
or raw event payload field. It stores identifiers and routing classification
only. Suppression policy is represented as a boolean hook; focus-aware policy
is deferred to P9.3.
