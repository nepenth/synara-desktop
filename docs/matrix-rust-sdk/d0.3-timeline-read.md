# D0.3 — native opened-room timeline sole owner

## Outcome

For a desktop session reported as `logged_in` by the Rust host, the opened-room
read path now mounts a native timeline view instead of the matrix-js-sdk
`RoomTimeline`. Rust owns one `matrix-sdk-ui::Timeline` per opened room beside
the live `Client` and `SyncServiceOwner` introduced by D0.1/D0.2.

There is no backend selector and no token-bearing IPC. Non-desktop sessions, or
desktop sessions not owned by Rust, retain the existing web timeline.

## Commands

- `matrix_timeline_open(room_id)` validates the room, creates or reuses its live
  SDK timeline, and returns the current snapshot.
- `matrix_timeline_snapshot(room_id)` returns the current projection for an
  already-open timeline. The desktop polls this command once per second for
  live changes.
- `matrix_timeline_paginate(room_id, dir)` paginates the retained SDK timeline
  in `backwards` or `forwards` direction and returns the updated snapshot.

All three commands are registered in the Tauri handler and explicitly allowed
for the localhost main webview.

## Privacy boundary

The product DTO contains only session generation, room ID, stable item and
event IDs, sender MXID, event type, origin timestamp, display body, and the
back-pagination end flag. Message bodies come from successfully materialized
SDK message content. Redacted and unable-to-decrypt events use fixed
placeholders. Unsupported event shapes use a fixed placeholder. Raw event
JSON, encrypted content, ciphertext, session keys, access tokens, refresh
tokens, and passwords never cross IPC.

## Known residual

- The first native timeline renderer is intentionally not virtualized. Large
  histories will need the existing viewport/virtualization behavior restored
  on top of native DTOs in a follow-up.
- Live updates use bounded one-second snapshot polling rather than streamed
  ordered diffs. Rust remains the source of truth throughout.
- Crypto UTD events render a stable placeholder. Key-recovery progress and
  richer late-decryption UX are deferred to the crypto-polish slice.
- Focused-event opening, reactions, rich media/state rendering, read markers,
  receipts, and viewport restoration are not yet projected by this slim read
  cutover.
- Sending remains D0.4. This change does not add a native send command or a
  second sync/login backend.
