## Executive summary

This task defines **Synara-owned domain DTOs** used over Matrix IPC (plan P1.4,
§3.2 product-owned projections, §6.1–6.4 contract foundation). Parallel Rust and
TypeScript representations share JSON fixtures and pure unit tests.

Product meaning first — **not** a `matrix-js-sdk` / Ruma object-graph clone.

**In scope:** session, room summary, member, timeline item, relation, receipt,
typing, upload, media, security, notification, search, space, thread, and widget
DTOs; fixtures; design note; parse helpers; round-trip tests.

**Out of scope (explicit):**

- Production Matrix login/sync/Client construction
- Tauri `invoke_handler` registration for Matrix product commands
- Switching the frontend off `matrix-js-sdk`
- Dual-backend / SDK selector
- Expanding IPC envelope kinds beyond P1.3 control surface
- Expanded contract-test suite — **P1.5**
- Architectural CI guardrails — **P1.6**
- SDK → DTO mapping in a live supervisor — Phase 2+

Product Matrix runtime remains **only** `matrix-js-sdk`.

## 2. Wire conventions

| Convention | Rule |
|------------|------|
| Field names | **camelCase** on JSON (Rust `rename_all = "camelCase"`) |
| Enum / kind discriminators | **snake_case** (`ready`, `logged_out`, `reaction_summary`) |
| Timeline tagging | Internally tagged on `kind` |
| Media | Handles / mxc URI strings / paths only — **never** byte arrays |
| Secrets | **No** `accessToken`, `refreshToken`, recovery keys, passwords |
| SDK types | **No** `matrix_sdk` / Ruma types in DTO modules |

Policy constant (Rust + TS): `FORBID_MEDIA_BYTES_OVER_JSON_IPC = true`.

Forbidden wire field names are listed in `FORBIDDEN_WIRE_FIELD_NAMES` and
asserted in fixture/privacy tests.

## 3. DTO families

### 3.1 Session — `SessionSnapshot`

| Field | Notes |
|-------|-------|
| `sessionGeneration` | `u64` / number |
| `userId`, `deviceId`, `homeserverUrl` | Opaque account identifiers |
| `displayName?`, `avatarUrl?` | Avatar is mxc/handle string only |
| `lifecycle` | `empty`…`wiping` (incl. `logged_out`) |
| `cryptoReady` | boolean |
| **Never** | `accessToken`, `refreshToken` |

### 3.2 Room summary — `RoomSummary`

Room list/nav projection: `roomId`, optional name/alias/avatar, `membership`,
`isDirect`, `isEncrypted`, optional `joinRule` string, unread/highlight counts,
`markedUnread`, optional `notificationMode`, `lastActivityTs`, bounded `heroes`,
optional tombstone successor.

### 3.3 Member — `RoomMember`

Per-room member: ids, display/avatar, `membership`, `powerLevel`, optional
`isDirectTarget`.

### 3.4 Timeline item — `TimelineItem`

Internally tagged on `kind`:

| kind | Role |
|------|------|
| `message` | Text preview body, msgtype, relations, local echo, edit/redact flags, thread root |
| `state` | `stateKey`, `stateType` string, optional summary |
| `membership` | Target user + change summary |
| `reaction_summary` | Target event, key, count, me |
| `redacted` | Optional `redactedBy` |
| `encrypted_unavailable` | Optional reason (no ciphertext) |
| `date_separator` | UI helper (`dayKey`) |
| `read_marker` | UI helper |
| `other` | Safe fallback — no raw full content dump |

Stable `itemId` for virtualization (may equal `eventId` or local id).

### 3.5 Relation — `RelationRef`

`relType` open string (`annotation`, `m.replace`, `m.reference`, `m.thread`, …),
target `eventId`, optional room/sender/key.

### 3.6 Receipt — `Receipt`

`roomId`, `eventId`, `userId`, `receiptType`
(`read` / `read_private` / `fully_read`), optional `ts`, `threadId`.

### 3.7 Typing — `TypingSnapshot`

`roomId` + bounded `userIds[]`.

### 3.8 Upload — `UploadJob`

Job id, optional room, file name/mime/size metadata, `state`, `progress01`,
optional `mediaHandleId` on complete. **No file bytes.**

### 3.9 Media — `MediaHandle`

Opaque `handleId`, optional mxc/source/mime/size/dimensions/duration,
`thumbnailHandleId`. **No bytes**, no encryption key material fields.

### 3.10 Security — `SecurityStatus`

`crossSigningActive`, `backupStatus`, `recoveryStatus`, `verificationState`,
optional `deviceCount`, `hasPendingVerificationRequests`. No keys/secrets.

### 3.11 Notification — `NotificationCandidate`

OS notification candidate: ids, `kind`, privacy-filtered `title`/`body`, optional
route, focus-suppress flag, `isEncrypted`.

### 3.12 Search — `SearchResult`

Query, optional room scope, result rows (event/room/ts/sender/snippet), optional
pagination / total.

### 3.13 Space — `SpaceSummary`

Space room + children (`roomId`, order, suggested) + optional parents.

### 3.14 Thread — `ThreadSummary`

Root event, reply count, latest event/ts, participated, optional unread.

### 3.15 Widget — `WidgetSession`

Element Call / custom: widget id, room, kind, lifecycle state, optional URL
(no token query secrets required on wire), `hasActiveCall`.
